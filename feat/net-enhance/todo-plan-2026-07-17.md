### P0 — net-bench 切换数据源：从 eBPF net_stats 到 /proc/net/dev

**来源**：`net-bench-proc-net-dev-plan.md`（2026-07-10 决策）+ 周报计划

**背景**：
- `DeviceHandle` 内置的 `AtomicU64` 计数器与 eBPF net_stats 做的是同一件事（统计收发包字节数），但内置计数器在知道字节数的代码行直接 `fetch_add`，不存在 ABI/内联/布局问题
- eBPF net_stats 的 RX 字节计数因 `RxToken` 内联阻塞
- `/proc/net/dev` 是 Linux 生态标准接口，summarize.py 解析它比解析自定义 `NET_STATS_BEGIN/END` 更自然
- 当前 `summarize.py` 的 `NetStatsSnapshot` 仍使用旧的 8 字段格式（tcp/udp × tx/rx × pkts/bytes），与 phy 层重构后的 4 字段格式（tx/rx × pkts/bytes）不兼容

**方案**：

1. **net-bench 集成 `/proc/net/dev` 快照采集**
   - 在 guest 测试脚本（`net-bench-common.sh`）中，iperf3/netperf 调用前后分别 `cat /proc/net/dev`，输出标记块供 host 侧解析
   - 格式可参考现有 `NET_STATS` 块机制，但字段对齐 `/proc/net/dev` 标准格式

2. **summarize.py 改造**
   - 移除或标记 deprecated：`NetStatsSnapshot`、`parse_netstats()`、`render_netstats()` 中的旧 8 字段格式
   - 新增 `/proc/net/dev` 差值解析（测试前后快照对比）
   - 保留对 iperf3 JSON（`sum_received`/`sum_sent` 中的 `bytes` 字段）的应用层统计——iperf3 报告的是应用层确认传输量，与 `/proc/net/dev` 的 L2 帧字节数互补

3. **eBPF net_stats 去留**
   - 暂不修改 `apps/starry/ebpf/net_stats/` 代码
   - 保留作为独立的 eBPF/kprobe 基础设施验证工具（`--test` 模式）
   - 不再作为 net-bench 吞吐测试的数据源

**涉及文件**：
- `apps/starry/net-bench/core/net-bench-common.sh`
- `apps/starry/net-bench/core/summarize.py`
- `apps/starry/net-bench/prebuild.sh` — 不再依赖 net_stats 二进制

### P1 — 补充 /proc/net/dev 缺失维度（packets/errors/drops）

**来源**：周报"统计维度扩展" + `network-performance-testing-analysis.md` P0 建议

**当前状态**：
- `NetDevStats` 仅有 `rx_bytes/rx_packets/tx_bytes/tx_packets` 4 字段（`net/ax-net/src/router.rs:86-93`）
- `DeviceHandle` 仅有 4 个 `AtomicU64` 计数器（`router.rs:281-284`）
- `render_proc_net_dev()` 将 errors/drops/fifo/frame/compressed/multicast 全部硬编码为 0

**注意**：`packets` 维度在 `NetDevStats` 中已有字段，`/proc/net/dev` 也已经输出。此处"补充"指 `errors`、`drops` 等当前硬编码为 0 的字段。

**方案**：

1. **drops 计数**
   - RX drops: 在 `device_rx_worker()` 中，当 `local_batch` 满、`buffer.enqueue()` 失败时计数
   - TX drops: 在 `device_tx_worker()` 中，当 `Device::send()` 返回 0（非 pending ARP 情况）时计数
   - 在 `DeviceHandle` 中新增 `rx_drops: AtomicU64`、`tx_drops: AtomicU64`

2. **errors 计数**
   - RX errors: 在 `EthernetDevice::handle_frame()` 中，无效 EtherType、校验失败等路径计数
   - TX errors: 在 `EthernetDevice::send_to()` 中，发送失败路径计数

3. **NetDevStats 扩展**
   - 新增 `rx_errors/rx_drops/tx_errors/tx_drops` 字段
   - 更新 `render_proc_net_dev()` 输出，替换硬编码的 0

4. **fifo/frame/compressed/multicast/colls/carrier**
   - 这些是硬件相关字段，QEMU virtio 环境暂无对应事件源
   - 保持 0 并添加注释说明

**涉及文件**：
- `net/ax-net/src/router.rs` — `NetDevStats`、`DeviceHandle`、worker 计数点
- `net/ax-net/src/device/ethernet.rs` — RX errors 计数
- `os/StarryOS/kernel/src/pseudofs/proc.rs` — `render_proc_net_dev()`

### P1 — 实现 /proc/net/snmp 等价接口

**来源**：周报"协议栈统计接口" + `network-performance-testing-analysis.md` P0 建议

**当前状态**：完全未实现。`/proc/net/` 下仅有 `arp` 和 `dev`。

**方案**：

1. **新增 `render_proc_net_snmp()`**
   - 位置: `os/StarryOS/kernel/src/pseudofs/proc.rs`
   - 注册: `net.add("snmp", SimpleFile::new_regular(...))`

2. **统计来源**
   - StarryOS 使用 smoltcp 0.13.1，其 `tcp::Socket` 和 `udp::Socket` 没有内置累计统计字段（仅瞬时队列深度、容量、状态）
   - 需要在 `ax-net` 层新增协议栈健康度计数器：
     - Tcp: 在 `TcpSocket::send()`/`recv()` 中累加重传/乱序事件（需跟踪 smoltcp 内部状态变化）
     - Udp: 在 `UdpSocket::send()`/`recv()` 中累加错误事件
     - Ip: 分片统计（当前 smoltcp 0.13.1 默认不分片）

3. **简化方案（建议先实施）**
   - smoltcp 的 socket 统计接口有限，深入改动成本高
   - 先实现框架和可获取的字段（如基于现有 `DeviceHandle` 计数器的 Iface 级别统计）
   - 对需要 smoltcp 内部状态的字段（TcpRetransSegs、TcpInOfOrder 等），标记为 "TODO: needs smoltcp upstream"

**涉及文件**：
- `os/StarryOS/kernel/src/pseudofs/proc.rs` — 新增渲染函数与注册
- `net/ax-net/src/` — 新增协议栈统计数据结构（可能新增 `tcp_stats.rs` / `net_stats.rs`）

### P2 — 应用层有效负载统计与分层对比

**来源**：周报"应用层统计增强"

**背景**：
- 当前 `/proc/net/dev` 提供 L2 帧字节数（含全部协议头开销）
- iperf3 提供应用层确认传输量
- 两者之间的差值可以量化协议开销占比，但当前未在结果中系统化展示

**方案**：

1. **summarize.py 增强**
   - 对比 iperf3 报告的 `sum_received/sum_sent bytes`（应用层）与 `/proc/net/dev` 增量（L2 层）
   - 计算并展示协议开销占比
   - 示例输出：
     ```
     TCP 单流上行:
       L2 (eth frame): 10.24 GB
       L7 (iperf3):    9.20 GB (10.2% protocol overhead)
     ```

2. **无需修改 StarryOS 内核**：利用已有数据源即可完成分层对比

**涉及文件**：
- `apps/starry/net-bench/core/summarize.py`
