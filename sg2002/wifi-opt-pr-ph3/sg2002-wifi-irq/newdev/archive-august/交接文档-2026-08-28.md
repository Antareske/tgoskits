## 三、当前情况（截至 2026-08-28 下班）

### 3.1 已达成

- **开机成功**：8.log 完整走通 ReadRevision → UploadMain → UploadPatch → StartApplication → Stabilize → Reinitialize → StackStart → ArmChipInterrupt → Complete → Ready → Welcome to Starry OS!。
- 工具已上板可执行（AP/开放 STA 入口可用，WPA2 待熵）。

### 3.2 未解决（核心）：MM_ADD_IF_REQ（0x0006）固件无应答

**现象**（wiftctl.log，65s 时刻）：`wifi-ctl eth0 ap SG2002 6` → `mailbox begin id=0x0006 expected=0x0007` → `flow: credits=125 raw=0x7d`（帧写入成功）→ **5 秒无 CFM → MailboxTimeout → 设备 fail() 判死** → commit 返回错误 → 工具 "ioctl: Bad address" 退出。

**已排除**（与旧板测驱动 `0fc626fa4^` 逐字节对照）：
- 消息 ID 正确（厂商枚举 MM_ADD_IF_REQ=6/CFM=7）；
- payload 布局正确（type=2=MM_AP @0、padding @1、mac @2..8、p2p @8，共 10 字节——与旧驱动注释一致）；
- 命令顺序正确（ADD_IF → MM_START(0x0002) → SET_FILTER(0x000e) → beacon(0x1c08) → APM_START，与旧驱动 apm.rs 一致）。

**剩余候选**（按可能性排序）：
1. **OTHER 位恒置**（最可疑）：固件经 sleep_reg(0x01) bit0 软中断置位 OTHER，主机未清该位 → `interrupt_block_count` 恒返回 None → Count 永远重试 → 5s 超时。厂商 aicsdio.c 对 OTHER 置位是"清 sleep_reg bit0 后仍读帧"；新驱动只重试。这是三轮审查附录 C 反复列出的观察项，如今疑似命中。
2. 固件主程序未运行（StartApplication 成功但固件实际未跑）。
3. 全零 MAC：设备 MAC 从未设置（8.log 中 eth0 mac=00:00:00:00:00:00；StackStart CFM 不含 MAC——厂商结构是 is_5g_support+vendor_info），ADD_IF 携带全零 MAC 可能被固件忽略（注：若被"拒绝"应有 CFM 带错误 status，当前是**无应答**，故本候选较弱）。

**判别方法**：count raw 值——恒 `0x8x` = OTHER 位（候选 1）；恒 `0x00` = 无帧（候选 2/3）。**但 count raw 已降 debug，当前板测日志看不到**。

### 3.3 设备 Failed 不可逆

`fail()` 后核心永远 `Idle`（Stopped | Failed => Idle），**没有重启 wifi 的机制**。第二次板测会话（222s/261s，未存文件）已证实：设备死后 AP commit 21ms 快速失败（提交路径拒绝，无 mailbox begin）、STA commit 报 EINVAL——两者都是死设备的拒绝症状，不是新问题。**每次板测需重启系统恢复**。

### 3.4 错误映射粗糙（误导性 errno）

`StarryError::BadState → Errno::EFAULT`（"Bad address"）与 `InvalidInput → EINVAL`——设备失败被映射成与真实原因无关的 errno，已造成一次解读弯路。修复方向：BadState 改 ETIMEDOUT/EIO 类。

### 3.5 遗留观察项（已登记在追踪文档，均未触发/未验证）

- OTHER 位行为（即 3.2 候选 1，当前最相关）
- 坏帧重试无计数上限（flow 有 100 次上限；坏帧靠 5s deadline）
- count>1 多块读吞 CFM（已有测试钉契约：混合批 → MailboxTimeout）
- Shutdown 路径 rdif 无生产者（潜在死路径，核心侧已修失配+有测试）
- D80 flow_credits 按 0x7F 掩码（厂商 D80 不掩码，安全方向）
- 每笔 TX 前厂商会 wakeup，新驱动仅 VendorSetup 一次（后续 mailbox 若芯片睡眠会 flow 恒 0）
- 串口捕获丢行（8.log 部分恢复；count/read 降 debug 已大幅缓解刷屏）
- 内核 wext 无权限检查（root shell 场景无碍；HTTP 控制服务场景需加固）
- WPA 熵源：SG2002 urandom 后端是软件 PRNG（种子=时间^计数器^栈地址），接熵前须确认芯片 TRNG
