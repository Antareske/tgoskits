## 3. 当前问题状态

### 问题 5：AP 可见但 PC 加入无响应 —【收敛到 AP 态配置，未修】

- 全满 MAC 架构下 auth/assoc 由固件自主完成，主机不在管理帧环内；STA 判别（10.log）证明空口 RX 整体正常 → 疑点为 AP 态 RX filter（`open_access_point_commands` 硬编码 `0x1502868c`，与厂商 `RWNX_DEFAULT_RX_FILTER` 的对应关系未核对）或 AP 专用固件配置缺失。

### 问题 6：WPA2 启动熵缺失 —【板测 workaround 已出，长期修复待办】

- 熵链 `ax-net → axhal → axplat-dyn → somehal → someboot` 只接受 UEFI RNG 或 FDT `/chosen/rng-seed`（恰 32 字节）；SG2002 启动链两者均无，内核按设计拒绝兜底。
- **上游 #2222 已实现机制**：axbuild `prepare_for_secure_wifi`（`scripts/axbuild/src/starry/boot_entropy.rs`）以主机随机数注入临时 DTB 副本——但**只在 `run_board_artifact`（CI `starry run` 路径）接线**，裸 build 不调用。
- 本流程 workaround：构建期 `openssl rand -hex 32` → dtc 注入临时 DTB → update-kernel `--dtb` 只进本次镜像；**资产 DTB 保持原版**（22679 字节 sha256 `8d71cc…`）。同镜像跨重启复用种子（板测可接受）。

### 问题 7：iperf 负载后数据面停摆 —【已修复，板测确认（18.log 三次 iperf 全过）】

- 症状：iperf3 一轮后双向 ping 断；控制面一度存活（SM_DISCONNECT 有 CFM）但随后 SM_CONNECT 主机侧 `Sdio(Timeout)`；最终固件断连 reason 1；wifi-ctl 后逐字符回显（CPU 饥饿）。
- 假说 1（`c7a9cab61`，已提交）：OTHER 软 IRQ 未确认 → CARD_INT 电平风暴。板测（12.log）未根治；13.log 全程 `other=0`——本次冻结路径不经过 OTHER，该修复既未触发也未证伪。
- 假说 2（未提交）：count 120 误读为 120 块 → 61KB 超长 FIFO 读挂死 SDIO 数据引擎。板测（13.log）**部分兑现**：CPU 饥饿/逐字符回显消失、冻结期间系统全程可交互（读不再挂死），但数据面停摆保持。
- **13.log 冻结证据（诊断心跳）**：iperf 客户端 67.4s 连接成功后 2s 突发窗口（+22 CARD_INT、RX +214KB、TX 写 26 帧、流控轮询 1619 次仅 26 次获信用），69.4s 起永久冻结 258s：0 CARD_INT、0 RX、0 TX、**0 信用**；流控重试（读 fn1 0x03）~865 次/s 恒定（总 224943）；主机事件循环与 SDIO 总线全程健康。第二次 `iperf3 -s` 监听成功但 PC 的 SYN 从未到达——空口 RX 一并死亡。PC 侧：iperf 第 1 秒 3.38MB@28.3Mbit/s 后全 0，Retr=0、cwnd 冻结 131KB。
- **判定**：冻结签名三次板测一致（12/13/14.log：突发 1-2s 后永久 0 CARD_INT/0 RX/0 信用，主机侧 ~862/s 流控轮询恒定）。**全部硬件/固件侧假说已排除**：① patch 配置缺失——已移植并板上生效（14.log），板测证伪；② 固件变体不配对——板端 vendor Linux 主固件 sha256 与 starry 完全一致（`ffb49ede…`），且 **vendor Linux 同 STA 场景 iperf 一切正常（用户实测）**——彻底排除；③ OTHER 软 IRQ/61KB 读——13/14.log 证伪或未触发。**冻结确认为 starry 驱动 STA 数据面实现缺陷**。剩余差异点候选：① **接收扫描语义**——厂商 D80 IRQ handler `while(intstatus)` 循环读到 0 排空全部数据，starry 有界单次扫描（每次 CARD_INT 只读一批）；② TX 帧格式/单帧写 vs 厂商聚合写；③ 流控重试语义（厂商退避+丢帧，starry 1ms 无限钉帧）；④ parse 不支持 AMSDU（独立真 bug）。次要发现：⑤ 冻结后固件侧是否有待发数据未知（探针未做）。
- **判别实验状态（18.log 后）**：问题 7 已根治并收敛提交（见第 1 节 8 笔提交）。三层根因链：① rearm 门控（15.log 第一层，`79951d9b8`）；② 流控判据 off-by-one（`9439e4bea` 内）；③ 流控信用 7 位掩码把 0x80 掩成 0（17.log 第二层，`9439e4bea` 内）。18.log 三次 iperf 全过（下载 31.2Mbit/s、上传 17.4Mbit/s、双向同时跑满 10s，全程 flow_retry=0）。遗留（用户裁定）：问题 8（S1 业务拒绝幸存语义）、问题 5（AP filter 对照实验）、parse AMSDU 丢帧层位、流控退避/丢帧语义对齐厂商。

### 问题 8：开机首次连接偶发被固件拒绝 —【已登记，未修】

- `SM_CONNECT_CFM status 1`，重启可成功；厂商路径由上层重试，本启动事务单次尝试。方向：启动事务有限重试或连接前等待。
