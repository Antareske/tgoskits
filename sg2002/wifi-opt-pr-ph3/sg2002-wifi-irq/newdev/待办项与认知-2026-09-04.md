## 1. 问题 8：开机首次连接偶发被固件拒绝（CO_FAIL）

- **现象**：10-1.log `firmware rejected message 0x1802 with status 1`（SM_CONNECT_CFM status 1 = CO_FAIL），启动事务单次尝试 → QueueInit panic；同一镜像重启多次后可成功。
- **已掌握认知**：
  - 厂商路径由上层 wpa_supplicant 重试，驱动不做重试；dev 启动事务单次尝试。
  - 结构性解法（OCR S1，principal-1/2 独立命中）：**业务拒绝（FirmwareRejected/WPA 协议类）不应升级为设备级 Failed**——现状 `fail()` 置 `AicState::Failed`、清空 mailbox/control，一次拒绝=整卡死亡。建议业务拒绝走 `ControlFailed` 幸存语义（驱动内异步断连路径已有先例 `data_plane.rs` SM_DISCONNECT_IND 分支），设备保持 Ready；SDIO/超时/总线类错误保留 fail()；在事务调用方（ax-net 启动事务/wifi-ctl）加有界重试。
  - 相关产品决策（OCR CQ5）：WiFi 子系统失败后当前唯一恢复手段是重启——是否接受"WiFi 子系统可重建"的长期设计，还是要求驱动核心自带控制面重试，待用户裁定。
- **待办**：按 S1 落地（业务拒绝幸存语义 + 上层有界重试），需先与用户确认恢复语义产品形态。

## 2. 问题 5：AP 可见但 PC 加入无响应

- **现象**：7.log AP 事务成功、beacon 正常（PC 可搜到 SG2002），PC 发起 auth/assoc 无响应；无驱动侧指示日志。
- **已掌握认知**：
  - STA 态空口 RX 全通（10.log 全链）→ RX 通路整体正常，问题收敛到 AP 态配置。
  - filter 位差（OCR S7 已核）：starry AP filter `0x1502868c` vs 厂商 `RWNX_DEFAULT_RX_FILTER=0x35078788`——缺 PROBE_REQ(8)/OTHER_DATA(29)/PS_POLL(18)/BAR(16)，多 MULTICAST(2)。但 auth/assoc 落在 OTHER_MGMT(15)/MY_UNICAST(7)，两者均在 starry 集合内——**位差只能解释"主动探测无回应"，不能解释 auth/assoc 无响应，是强候选但非充分解释**。
  - AP 事务后非 SM 指示全部降为 trace——7.log"无任何指示日志"可能是观察面太暗，判别需把 Indication 提级 info。
  - **AP 功能目标范围（OCR CQ1，待用户裁定）**：若目标是"关联+DHCP+上网"全链，当前 AP 模式无 peer 学习路径（`link.tx_indices()` 仅经 SM_CONNECT_IND 安装），即使 filter 修复，主机也无法给站点发 DHCP offer——投入范围取决于该答案。
- **待办**：① 用户裁定 AP 目标范围；② filter 常量按模式拆 STA/AP（AP 换厂商默认位集做对照实验，STA 不动）；③ AP 板测镜像把 Indication 提级 info；④ 预定义验收标准（testing-1：满载 ≥N 分钟 + 恢复判定 + 三连拍 + 三次运行全过）。

## 3. parse 层 AMSDU 丢帧（独立于冻结）

- **现象**：14.log（patch 开启 AMSDU_RX）应用层 0 字节交付；13.log（无 patch）60% 交付（读 214KB/交付 128KB）。
- **已掌握认知**：
  - AMSDU 拆包已有实现：`data_plane.rs` `decapsulate_amsdu`（QoS 位 0x80 判聚合、逐子帧拆以太网，有测试）。
  - `events` 队列满 256（`RX_CAPACITY`）时接收帧**静默丢弃**——13.log 40% 丢弃的部分来源。
  - 14.log 100% 丢弃的具体层位未定位：聚合帧是否到达拆包路径、还是被 parse_fifo/容量丢弃拦截，未查。
- **待办**：定位 AMSDU 开启后丢帧层位（对照 13/14.log 数据面路径），修复后与 RX_CAPACITY 丢弃语义一起收尾。

## 4. 流控退避/丢帧语义对齐厂商（低优先）

- **已掌握认知**：厂商数据面流控 `FLOW_CTRL_RETRY_COUNT=50`、退避 200µs→1ms→10ms、超限**丢帧**（上层 TCP 重传恢复）；starry 数据面 1ms 无限钉帧（问题 7 修复后信用正常时不触发，但语义未对齐）。邮箱流控 starry 已有 `MAX_MAILBOX_FLOW_RETRIES=100` 上限。厂商信用单位 BUFFER_SIZE=1536（旧驱动）vs starry 512——修复后 V3 读原始字节，单位语义未被证实影响。
- **待办**：数据面流控加退避与超限丢帧（与厂商语义对齐），回归测试先行。

## 5. 问题 6 长期方向：WPA2 启动熵

- **已掌握认知**：熵链 `ax-net → axhal → axplat-dyn → somehal → someboot` 只接受 UEFI RNG 或 FDT `/chosen/rng-seed`（恰 32 字节）；SG2002 启动链两者均无。上游机制 `scripts/axbuild/src/starry/boot_entropy.rs`（`prepare_for_secure_wifi`）只在 `run_board_artifact`（CI starry run）接线，裸 build 不调用。当前板测 workaround：每镜像构建期注入一次性 rng-seed（`tmp/axbuild/rngseed.dtb`，FDT sha256 `014a9b11…`），资产 DTB 保持原版（22679 字节 sha256 `8d71cc…`）。
- **待办**：把熵注入按上游语义接线到镜像构建流程，或 SG2002 平台 TRNG 接入 someboot capture（恢复每次运行新鲜种子）。涉及 axbuild 改动，需上游评审。
