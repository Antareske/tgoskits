# AIC8800 优化文档集（目录说明）

本目录是 **AIC8800 数据面优化这条工作线**的文档集。工作分支固定为 `sg2002/wifi-opt`
（见 `aic8800-optimization-tracker.md` 的「分支与提交」）；本目录整体**不被项目追踪**，
因此不受项目文档规范约束，但也**不得**反向成为项目的引用来源（正式文档不引用本目录）。

本工作线按 2026-09-27 的 OCR 审查划分阶段。第一阶段包含 OCR 审查前已经提交的 credit 记账、探针、TX 聚合、RX 扫描实验和 owner park 观测；第二阶段从 OCR 结论开始，首先处理普通数据 confirmation、typed 性能统计和默认 RX defer 策略。阶段划分只表示证据和交付边界，不把 OCR 审查中的待测收益写成已完成结论。

第二阶段的首轮板测采用少烧录策略：先用第一阶段已有日志作为历史基线，只构建一份第二阶段镜像并在同一次启动中完成连接、TCP TX、TCP RX 和双向检查；只有新镜像异常或结果无法作出工程决策时，才追加旧镜像对照。

## 2. 写在哪一份里（避免文档漂移）

- **新的事实/读数** → 先写进 `aic8800-optimization-tracker.md` 的当轮周期（改动-测试-现象），
  再把它并进 `aic8800-bottleneck-analysis.md` 的对应条目。**不要**为此新开一份文档。
- **结论被推翻** → 在瓶颈文档里把原条目改为"已更正 + 现结论 + 依据"，
  在跟踪文档里保留原判读并标注更正；不删除、不改写历史日志。
- **新的改动方向/阶段** → 写进 `aic8800-async-optimization-plan.md` 的对应阶段（或新增阶段），
  不在瓶颈文档里写方案。
- **一次性的分析/审查** → 写成 `probev<N>-<主题>-<日期>.md` 作为单轮专文，
  只把结论并入上面三份；专文本身不再更新。
- **新开一份文档**只在"主题与现有各份都不同、且会长期维护"时才做，并在本文件的第 1 节登记。

## 3. 写作要求

- 每条结论带**证据**：日志文件的窗口/行、代码位置（`文件:行`）、或厂商源码位置；带**日期**。
- 数字区分**实测**与**折算**（折算要写换算口径），未验证的写**推论**。
- 涉及厂商行为的结论，注明出处到文件与函数（例：`aicwf_sdio.c` 的 `aicwf_sdio_hal_irqhandler`），
  并记下与本仓库锁定的 vendor commit 是否同版（设计文档记录的是 `d4003f15b…`）。
- 不写"项目没有采取 X"之类的返工噪声；只留正向结论与仍开放的空白。
- 原始日志（`.log`）与已归档专文**不改**；需要更正就在现行文档里写更正。

## 4. 与代码/提交的关系

- 代码改动只在 `sg2002/wifi-opt` 上做；每轮的提交哈希记进跟踪文档的周期条目，**每份镜像对应的提交记进跟踪文档「分支与提交」下的镜像表**（镜像的 `.json` 由构建脚本写入当时的 `HEAD`）。
- 上板的探针插桩属临时改动，开 PR 前必须移除；移除记录写在跟踪文档里。
- 板测日志按惯例落在 `C:\Users\Asta\Desktop\logs`，需要时把当轮用到的日志**拷贝**进本目录
  （原始文件不改，命名 `probev<N>-board-<日期>.log`）。
